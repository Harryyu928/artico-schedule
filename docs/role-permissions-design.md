# ARTiCO 教务系统 - 角色权限与页面视图设计

## 一、角色层级体系

| 层级 | 角色 | 说明 | 数据访问范围 |
|------|------|------|-------------|
| 100 | 管理员（顾问主管） | 系统最高权限 | 全部数据 |
| 60 | 规划顾问 | 负责学生选课指导 | 负责的学生 + 关联导师的记录 |
| 40 | 全职导师 | 核心课程导师 | 自己的上课记录 + 教授的学生信息 |
| 20 | 兼职导师 | 辅助课程导师 | 自己的上课记录 + 教授的学生信息 |
| 10 | 学生 | 学习者 | 自己的选课单、时间表、课程记录 |

---

## 二、各角色可访问页面一览

### 管理员（顾问主管）
```
✅ 全部页面访问权限
- 仪表盘（全局数据概览）
- 工作流管理（全部流程）
- 学生管理（CRUD）
- 导师管理（CRUD）
- 课程管理（CRUD）
- 选课单管理（CRUD + 审批）
- 时间表管理（学生/导师）
- 排课管理（自动/手动）
- 上课记录（全部记录）
- 结课审核（审批权限）
- 课酬统计（全部导师）
- 数据导入、飞书集成
- 操作日志、系统设置
```

### 规划顾问
```
✅ 负责范围内的数据操作
- 仪表盘（负责学生的数据概览）
- 工作流管理（负责学生的流程）
- 学生管理（CRUD - 全部学生信息可见）
- 导师管理（只读）
- 课程管理（只读）
- 选课单管理（CRUD - 可创建/审批）
- 时间表管理（学生/导师）
- 排课管理（可排课）
- 上课记录（负责学生的记录）
- 结课审核（提交审核）
- 课酬统计（可见）
- 数据导入、飞书集成
- ❌ 操作日志、系统设置（无权限）
```

### 全职导师
```
✅ 自己相关的数据操作
- 仪表盘（自己的授课统计）
- 工作流管理（只读 - 相关流程）
- 学生管理（只读 - 教授的学生）
- 课程管理（只读）
- 选课单管理（只读）
- 时间表管理（自己的时间表 + 学生时间表只读）
- 排课管理（只读）
- 上课记录（CRUD - 自己的记录）
- 结课审核（提交结课申请）
- ❌ 课酬统计、数据导入、飞书集成（无权限）
```

### 兼职导师
```
✅ 最小权限范围
- 仪表盘（自己的授课统计）
- 学生管理（只读 - 教授的学生）
- 课程管理（只读）
- 时间表管理（自己的时间表）
- 排课管理（只读）
- 上课记录（CRUD - 自己的记录）
- ❌ 其他全部无权限
```

### 学生
```
✅ 仅个人相关
- 仪表盘（自己的学习进度）
- 课程管理（只读 - 课程列表）
- 时间表管理（自己的时间表）
- 选课单管理（只读 - 自己的选课单）
- ❌ 其他全部无权限
```

## 三、关键页面的数据过滤规则

### 3.1 上课记录页面 (`/class-records`)

| 角色 | 数据范围 | 默认视图 | 可切换视图 |
|------|---------|---------|-----------|
| 管理员 | 全部记录 | 按导师分组 | 全部视图 |
| 规划顾问 | 负责学生的上课记录 | 按学生分组 | 按学生/按时间 |
| 全职导师 | 自己的上课记录 | 按学生分组 | 按学生/按时间 |
| 兼职导师 | 自己的上课记录 | 按学生分组 | 按学生/按时间 |
| 学生 | 自己的上课记录 | 时间线视图 | 仅时间线 |

**数据过滤逻辑：**
```typescript
// 管理员：无过滤
// 规划顾问：WHERE student.consultantId = user.consultantId
// 导师：WHERE classRecord.teacherId = user.teacherId
// 学生：WHERE classRecord.studentId = user.studentId
```

### 3.2 学生管理页面 (`/students`)

| 角色 | 数据范围 | 操作权限 |
|------|---------|---------|
| 管理员 | 全部学生 | CRUD |
| 规划顾问 | 全部学生（重点标注负责的学生） | CRUD |
| 导师 | 仅教授的学生 | 只读 |
| 学生 | 仅自己 | 只读 |

### 3.3 导师管理页面 (`/teachers`)

| 角色 | 数据范围 | 操作权限 |
|------|---------|---------|
| 管理员 | 全部导师 | CRUD |
| 规划顾问 | 全部导师 | 只读 |
| 导师 | 仅自己 | 只读基本信息 |

### 3.4 选课单管理页面 (`/selection-forms`)

| 角色 | 数据范围 | 操作权限 |
|------|---------|---------|
| 管理员 | 全部选课单 | CRUD + 审批 |
| 规划顾问 | 负责学生的选课单 | CRUD + 审批 |
| 导师 | 相关学生的选课单 | 只读 |
| 学生 | 自己的选课单 | 只读 |

### 3.5 排课管理页面 (`/schedules`)

| 角色 | 数据范围 | 操作权限 |
|------|---------|---------|
| 管理员 | 全部排课 | 自动/手动排课 |
| 规划顾问 | 负责学生的排课 | 自动/手动排课 |
| 导师 | 自己的时间段 | 只读 |

## 四、用户与业务实体关联设计

### 4.1 数据库关联字段（已存在）

```sql
-- users 表已有以下关联字段
users.teacherId     -> teachers.id    -- 导师用户关联
users.studentId     -> students.id    -- 学生用户关联
users.consultantId  -> consultants.id -- 顾问用户关联（需确认是否有独立表）
```

### 4.2 前端用户上下文需要扩展

```typescript
interface User {
  id: string;
  name: string;
  role: UserRole;
  email?: string;
  avatar?: string;
  
  // 关联实体ID（新增）
  teacherId?: string;      // 导师ID（导师角色必填）
  studentId?: string;      // 学生ID（学生角色必填）
  consultantId?: string;   // 顾问ID（规划顾问角色必填）
  
  // 关联实体名称（方便显示）
  teacherName?: string;
  studentName?: string;
}
```
